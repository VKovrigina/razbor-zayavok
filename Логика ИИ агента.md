# Логика ИИ-агента (amoCRM + Telegram/почта)

## Общий контекст
- CRM: amoCRM
- Каналы: Telegram (приоритет, через личный аккаунт), Email (fallback)
- Бизнес: партнёрский отдел Альбато — обработка заявок на настройку интеграций, которые передаются партнёрам-интеграторам на оценку.
- Ответственный менеджер: **Варвара Ковригина**.
- Объём: ~5 заявок/день через эту воронку.
- **Текущий охват проекта:** только сценарий ниже (воронка Partners, этапы «Новый контакт» → «Первичные переговоры» → «Блок»). Дальнейшие этапы («Оценка», «Подключение» и т.д.) — вне охвата этой итерации.

---

## Сценарий: Первичный контакт по заявке (воронка Partners)

### 1. Триггер
Сделка попадает в воронку **Partners**, на этап **«Новый контакт»**.

### 2. Первое сообщение
Бот берёт из сделки/контакта:
- **Имя** — из привязанного контакта.
- **Telegram** (username) — из поля сделки.
- **Стек сервисов**, **Кейс** — из полей сделки.

И отправляет получателю (в Telegram, от личного аккаунта Варвары):

```
{Имя}, добрый день!
Меня зовут Варвара, я представляю партнерский отдел Альбато. Спасибо за ваш запрос!
Чтобы сориентировать вас по срокам и стоимости, мы работаем по следующей схеме:
• Оценка: Передаем ТЗ партнерам-интеграторам для оценки работ.
• Подключение: Помогаем выбрать тариф Альбато, необходимый для работы автоматизации.

Ваша задача выглядит сейчас так:
🔸Сервисы: {Стек сервисов}
🔸Задача: {Кейс}

Пожалуйста, убедитесь, что в вашем описании задачи есть:
1) Все сервисы, с которыми планируется работа
2) ТЗ описано подробно: какие данные необходимы, как их нужно обрабатывать и куда передавать

❗️Важно: соглашаясь с передачей вашей задачи на партнерскую биржу, вы также соглашаетесь с тем, что интеграция будет настроена с помощью сервиса Альбато.
За услуги интегратора и за тариф Альбато необходимо будет внести оплату.

Хотите ли вы что то еще добавить к своей задаче?

P.S. Сообщения в этом чате отправляет ИИ-помощник, поэтому в диалоге возможны неточности🙂
```

> Предупреждение о том, что переписку ведёт ИИ-помощник (P.S. выше), должно присутствовать в первом сообщении сценария. Остальные автоматические сообщения (напоминания, закрывающее сообщение, ответы по классификации А/Б/В) — без повторного предупреждения, так как контекст уже задан в начале переписки.

**Канал:** Telegram по умолчанию. Отправка на **Email** вместо Telegram, если:
- в сделке не заполнено поле Telegram, ИЛИ
- получатель — premium-аккаунт, блокирующий сообщения от незнакомых (техническая ошибка при попытке отправки).

Текст письма — тот же, по смыслу адаптированный под email-формат.

### 3. Ветвление по ответу клиента

**Любой ответ клиента (в любой момент, включая ответы на напоминания) → сделка переносится на этап «Первичные переговоры»** и дальнейшие напоминания отменяются. Дальше ответ классифицируется:

**А. Позитивный** — явное согласие, в том числе с дополнением деталей к задаче (клиент даёт больше информации, но не возражает и не просит оператора).
- Бот пишет: «Отлично, передаю вашу заявку на нашу партнерскую биржу. Как получу ответ - создам чат с нашим партнером, который будет заниматься настройкой».
- В amoCRM ставится задача на **Варвару Ковригину** — оформить задачу/ТЗ.
- Бот **прекращает** автоматическую обработку сообщений по этой сделке (дальше — зона ответственности Варвары).

**Б. Негативный** — маркеры: «неактуально», «позовите оператора» и подобные по смыслу.
- Бот отвечает в чате: извиняется и сообщает, что менеджеру уже передали информацию о необходимости подключиться к диалогу.
- В amoCRM ставится задача на **Варвару Ковригину** с текстом о том, что клиент негативный.
- Бот **прекращает** автоматическую обработку сообщений по этой сделке — дальше диалог ведёт Варвара вручную с того же аккаунта, бот не пишет ничего больше.

**В. Неоднозначный** — вопрос, на который бот не может ответить самостоятельно, и это не подпадает под А или Б.
- Бот пишет, что уточнит этот момент.
- В amoCRM ставится задача на **Варвару Ковригину** с текстом «уточнение».
- Бот **прекращает** автоматическую обработку сообщений по этой сделке до закрытия задачи вручную.

> Итого: **любая** эскалация (Б или В) полностью останавливает автоответы бота в этой сделке — чтобы не конфликтовать с ручными сообщениями Варвары с того же личного аккаунта. Возобновление — вручную (например, при закрытии задачи или смене этапа человеком; механизм возобновления уточнить на этапе реализации, если понадобится).

### 4. Цепочка напоминаний при отсутствии ответа

1. Первое сообщение отправлено, ответа нет.
2. **На следующий день в 14:00 МСК** (если это выходной — переносится на следующий рабочий день) — напоминание №1:
   ```
   Здравствуйте, ваша заявка актуальна?
   ```
3. Если снова нет ответа — **на следующий день в 14:00 МСК** (аналогично, с переносом с выходных на рабочий день) — закрывающее сообщение:
   ```
   Добрый день!
   Так как не получили от вас ответа, вашу заявку закрываем)
   В любом случае, остаемся на связи - будем рады помочь вам с интеграцией, когда станет актуально🌿
   ```
   Сделка переносится на этап **«Блок»**.
4. Email-канал (если используется вместо Telegram) — та же логика и те же сроки.

## Технические заметки и риски (для этапа реализации)

- **Отправка от личного Telegram-аккаунта (MTProto, напр. Telethon/Pyrogram)**, а не через Bot API — только так можно писать первым по username.
- ⚠️ **Риск ограничений/бана номера**: массовая переписка с личного аккаунта нарушает ToS Telegram. При ~5 заявок/день риск умеренный, но нужно закладывать: случайные задержки перед отправкой (не мгновенно по триггеру), разумные лимиты в час/день, обработку сигналов ограничения от Telegram (flood wait и т.п.).
- **Детект premium/приватности получателя** — по исключению при попытке отправки сообщения (например `UserPrivacyRestrictedError` в Telethon) → fallback на email.
- Нужно собрать до старта разработки: ID/учётные данные API amoCRM, ID пользователя Варвары в amoCRM (для назначения задач), ID полей сделки (Telegram, Стек сервисов, Кейс), точные названия этапов в воронке Partners, механизм триггера (вебхук amoCRM при смене этапа), тема письма для email-версии.
- Нужно хранилище состояния диалога по каждой сделке (когда отправлено сообщение, сколько напоминаний ушло, статус: ждём ответ / эскалировано / закрыто) — amoCRM сам по себе для этого не подходит, потребуется небольшая БД.
