## [Unreleased]

### Added
- Проект инициализирован переносом кода из `../ТГ агент` под `agentic-coding-template` pipeline
  (2026-07-23): amoCRM ↔ Telegram/Email агент партнёрского отдела Альбато, классификация ответов
  клиента через Claude. Сценарий и бизнес-логика не менялись, только структура проекта
  (AGENTS.md, RESEARCH.md, CLAUDE.md, WORKFLOW.md, `.claude/`, `tasks/`, `templates/`, `docs/`).
- **Cutover (2026-07-23):** runtime-состояние (`data/telegram.session`, `data/app.db`,
  `data/agent.log`) перенесено из `../ТГ агент` — этот проект теперь единственный источник
  боевого состояния, `../ТГ агент` decommissioned (код-архив без данных).
- **Анти-бан вариации первого сообщения (2026-07-23):** `core/templates.py` — 4 формулировки
  первого сообщения, случайный выбор при каждой отправке (`FIRST_MESSAGE_VARIANTS`).
- **База знаний (FAQ) на встречные вопросы клиента (2026-07-23, черновик):**
  `classify/faq.py` + `docs/faq-knowledge-base.md`. При ambiguous-ответе бот пытается подобрать
  готовый ответ из базы через Claude (`match_faq_sync`), отвечает клиенту и всё равно ставит
  задачу на Варвару с пометкой, что дан автоответ. ⚠️ Тексты ответов — плейсхолдеры, ждут
  реальных фактов (цены/сроки/условия) в `docs/faq-knowledge-base.md`.
- **Чеклист целостности задачи (2026-07-23):** `core/checklist.py` — стек: минимум 2 названных
  сервиса; кейс: описана проблема клиента ИЛИ данные для обработки (через Claude, фолбэк — длина
  строки). Не блокирует и не откладывает отправку — если данных не хватает, бот вставляет
  предупреждение прямо в основное первое сообщение, перед абзацем согласия на оплату
  (`core/templates.py: first_message`).
- **Тематические чек-листы (2026-07-23):** `core/checklist.py: assess_topic` — распознаёт 4 типа
  задач (ИИ-агент/чат-бот, Tilda+iiko, Яндекс Метрика, бот в Максе) и проверяет специфичные для
  темы детали (см. `_TOPIC_DEFINITIONS`). Если чего-то не хватает — эти вопросы ЗАМЕНЯЮТ
  закрывающий вопрос "Хотите что-то добавить?" в первом сообщении. Закрывающий вопрос теперь
  варьируется независимо от тела сообщения (`DEFAULT_CLOSING_QUESTIONS`).
- **Новые этапы CRM + примечание с ТЗ (2026-07-23):** воронка Partners расширена — «Первичные
  переговоры» теперь наступает сразу после отправки первого сообщения (не дожидаясь ответа),
  ответ клиента переводит сделку на «Уточнение ТЗ», а после классификации (positive/negative/
  ambiguous) сделка ВСЕГДА уходит на «Ручная проверка» (`amo_actions.move_to_clarification`,
  `move_to_manual_review`). При positive в сделку добавляется примечание с собранным ТЗ
  (`amo_actions.add_note`, `core/templates.py: spec_note`) — включает ответ клиента. Новые
  `.env`: `AMOCRM_STAGE_CLARIFICATION_ID=83028202`, `AMOCRM_STAGE_MANUAL_REVIEW_ID=87403378`
  (этапы уже существовали в amoCRM, ID получены через API).
- **Цепочка напоминаний доработана + этап «Молчание» (2026-07-23):** `process_scheduler_tick`
  теперь (1) перечитывает сделку из БД после лока и не шлёт напоминание, если ответ клиента уже
  пришёл; (2) перед отправкой проверяет РЕАЛЬНЫЙ текущий этап сделки в amoCRM
  (`amo_actions.get_lead_status_id`) и останавливает напоминания насовсем (`repo.stop_reminders`),
  если сделку вручную увели с этапов «Первичные переговоры»/«Молчание»/«Уточнение ТЗ»; (3) после
  напоминания №1 переводит сделку на новый этап **«Молчание»** (`amo_actions.move_to_silence`,
  `AMOCRM_STAGE_SILENCE_ID=82845866`, этап уже существовал в amoCRM). Та же цепочка теперь
  обслуживает и ожидание ответа на уточняющий вопрос бота из базы знаний на этапе «Уточнение ТЗ»
  (`repo.restart_reminder_cycle`).
- **FAQ включён, реальный контент для 3 пунктов (2026-07-23):** `FAQ_ENABLED = True`.
  `faq_price`, `faq_timeline`, `faq_who_is_integrator` заполнены реальными фактами (цена — после
  оценки партнёром + вопрос про частоту использования; сроки оценки — обычно день, максимум 2;
  партнёры — не сотрудники Альбато). Если ambiguous-ответ клиента совпал с одним из заполненных
  пунктов — бот отвечает сам и остаётся ждать реакции клиента (та же цепочка напоминаний), БЕЗ
  эскалации на Варвару; эскалация происходит только когда следующий ответ клиента классифицирован
  как positive/negative, либо очередной вопрос не находит совпадения в базе. Черновики-плейсхолдеры
  (`faq_albato_tariff`, `faq_free_estimate`, `faq_can_decline_after_estimate`,
  `faq_payment_timing`, `faq_multiple_services`) исключены из подбора структурно (`_USABLE_ENTRIES`)
  — Claude физически не может их выбрать, пока не заполнены реальными фактами.

### Changed
- ⚠️ Обнаружено: `ANTHROPIC_API_KEY` в `.env` пуст — все LLM-зависимые функции (классификация,
  чеклисты, подбор FAQ) сейчас работают на грубых non-LLM фолбэках (у FAQ фолбэка нет вовсе —
  без ключа `match_faq_sync` всегда возвращает `None`). См. `RESEARCH.md` (раздел вверху).
- `REPLY_AMBIGUOUS` (`core/templates.py`) переформулирован: «Ваш вопрос я зафиксировала, в
  ближайшее время с вами свяжется менеджер» — вместо прежнего «Уточню этот момент и вернусь с
  ответом», под сценарий, когда бот не нашёл ответа в базе знаний.
- Создан `.venv/` для локального запуска тестов и read-only проверок amoCRM API — у системного
  `python3` не было нужных зависимостей (см. `RESEARCH.md`, раздел «Тесты»).

## Convention

- **Added** — новая функциональность
- **Changed** — изменения существующей функциональности
- **Deprecated** — функциональность будет удалена
- **Removed** — функциональность удалена
- **Fixed** — багфиксы
- **Security** — security фиксы

Каждая запись = ссылка на PR + краткое описание для пользователя (не для разработчика).
